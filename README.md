# 変圧器オイル温度の予測 PoC — ETT データセット

電力用変圧器のオイル温度を数時間先まで予測し、**高温リスクの事前警告**として実運用に耐えるかを検証した PoC です。
公開ベンチマーク [ETT (Electricity Transformer Temperature)](https://github.com/zhouhaoyi/ETDataset) を使用しています。

報告スライド: [`reports/poc_report.pdf`](reports/poc_report.pdf)

---

## 1. 検証の設定

| 項目 | 内容 |
|---|---|
| ユースケース | 各時刻で N 時間先のオイル温度を予測し、閾値超過・急上昇を事前に警告する |
| 予測ホライズン | 1 / 3 / 6 / 12 / 24 時間先 |
| 予測対象 | 現在温度からの**変化量** `OT[t+h] − OT[t]`(後述) |
| 入力 | 温度と負荷 6 変数の**過去値のみ** + 時刻特徴。未来の負荷は使わない |
| 評価 | 2017-07〜2018-06 の 12 ヶ月を月次ローリング(各月、その月より前の全データで再学習) |
| 対象設備 | ETTh1・ETTh2(1 時間粒度、2016-07〜2018-06、各 17,420 時間) |

## 2. 結論

1. **設備によって予測の価値が大きく異なる。** 日内変動が大きい ETTh2 では 6〜12 時間先まで
   persistence(現状の閾値監視に相当)の誤差を **56〜59% 削減**。変動が緩やかな ETTh1 では 17〜21% に留まる。
2. **ETTh2 では 6 時間前の高温警告が実用水準。** 45℃ 超過を検知率 78% / 適合率 85% で事前警告できる
   (現状相当では 42% / 43%)。「6 時間以内に +5℃ 上昇」は現状では原理的に検知不能だが、本手法では 79% を検知。
3. **24 時間先はどの設備・どのモデルも persistence と同等。** 1 日先の温度は過去の温度・負荷だけでは決まらず、
   外気温などの外部データが不可欠。
4. **負荷 6 変数の寄与は小さい。** 負荷ラグの有無で精度はほぼ変わらず、未来の負荷を与えても改善しない。
   予測を支えているのは温度自身の履歴と日内周期。

### 精度(MAE [℃]、括弧内は persistence からの改善率)

| 設備 | モデル | 1h | 3h | 6h | 12h | 24h |
|---|---|---|---|---|---|---|
| ETTh1 | persistence | 0.50 | 0.91 | 1.32 | 1.73 | 1.74 |
| ETTh1 | **LightGBM** | 0.46 (−7%) | 0.75 (−17%) | 1.04 (−21%) | 1.37 (−21%) | 1.73 (−1%) |
| ETTh2 | persistence | 0.91 | 2.52 | 4.39 | 6.02 | 3.12 |
| ETTh2 | **LightGBM** | 0.38 (−58%) | 1.03 (−59%) | 1.82 (−58%) | 2.65 (−56%) | 3.06 (−2%) |

### 業務指標(ETTh2、6 時間前の警告)

| イベント | 現状相当 (persistence) | LightGBM |
|---|---|---|
| 45℃ 超過(498 件) | 検知率 42% / 適合率 43% | **検知率 78% / 適合率 85%** |
| 6 時間以内に +5℃ 上昇(1,519 件) | 0%(構造上検知不能) | **検知率 79% / 適合率 75%** |

閾値は評価期間の上位 5〜7% 相当を仮置きした値です。実運用では設備の許容温度で再定義が必要です。

## 3. EDA の主な示唆

| 発見 | 設計への反映 |
|---|---|
| ACF(lag1) > 0.99。持続性が非常に強い | persistence を必須ベースラインに。**温度そのものではなく変化量を予測**する |
| ETTh1 は 2 年で平均温度が 34℃ → 10℃ へ低下(負荷も半減) | 勾配ブースティングは学習範囲外を外挿できないため、変化量ターゲットが必須 |
| ETTh1 の 1 時間差分はほぼホワイトノイズ、日内振幅 ±1.4℃ | 予測可能性が低い。効果が限定的になることを事前に想定 |
| ETTh2 は日内周期が強く(±5℃)、差分にも周期構造が残る | 時刻の sin/cos と 24h 前後のラグを投入 |
| 負荷との相関はレベルで最大 0.5、差分で 0.1 以下。明確な遅れ構造なし | 負荷ラグは入れるが、**有無を比較して寄与を検証**する |
| 毎月 31 日の 01:00〜23:00 が全列コピー(元データ欠損の前方補完、両設備で 322 行) | `flag_artifacts()` でフラグ化し学習・評価から除外 |
| ETTh1 に 58 時間の全負荷ゼロ区間、OT = 0.00 が 111 行 | 同上。現状の閾値監視でも誤報源になる点をクライアントに報告 |

## 4. 設計上の主な意思決定

- **変化量を予測する** — レベルを直接予測すると、ETTh1 のように学習期間と評価期間で温度帯が変わる設備で木モデルが破綻する。
  変化量なら分布が安定し、予測値は `OT[t] + Δ̂` で温度に戻せる。
- **未来の負荷を使わない** — 予測時点で未来の負荷は未知。同時刻の負荷を入力に含めるのはリークにあたる。
  参考として「未来の負荷が分かる場合」(`lgbm_oracle_load`)も測定したが、改善しなかった。
- **月次ローリング評価** — 末尾 4 ヶ月固定のテストだと ETTh1 に高温イベントが 1 件も含まれず業務指標が測れない。
  12 ヶ月ローリングなら全季節が評価対象になり、「月次で再学習する運用」の再現にもなる。
- **ベースラインを常に併記** — persistence / seasonal naive に対する改善率で価値を測る。
- **業務指標をレベル依存・非依存の 2 本立てに** — 閾値超過だけだと温度帯が下がった ETTh1 で評価できないため、
  「N 時間以内に X℃ 上昇」も併用する。
- **データ品質フラグ** — 前方補完・センサ欠測を機械的に検出し、学習・評価から除外する。
- **テストを実装より先に書く** — 時系列パイプラインで最も危険なリークと時刻ずれを、
  「t 以降のデータを改変しても t の特徴量が変わらない」等のテストで機械的に検出する(`tests/test_features.py`)。

## 5. 限界と今後の改善方針

| 限界 | 改善方針 |
|---|---|
| 24 時間先は予測できない(外部要因が支配的) | **外気温・日射の予報データを投入**。公開気象データで効果を検証できる |
| 点予測のみ。警告は「予測値 > 閾値」の決め打ち | 分位点回帰で**超過確率**を出し、閾値を運用コスト(誤報 vs 見逃し)で最適化する |
| 閾値・イベント定義が仮置き | 設備の許容温度・保全規程に合わせて再定義。実際の警報記録・点検記録と突合する |
| 設備 2 台のみ、外挿性が未検証 | 複数設備での横断学習(global model)や、設備特性に応じた適用可否の判定基準づくり |
| 15 分粒度(ETTm)・深層学習モデルは未検証 | 短ホライズンの改善余地を確認。ただし本結果からは大幅な改善は見込みにくい |
| 静的なバックテストのみ | ドリフト検知と再学習トリガを含む運用設計。本 PoC の月次再学習は最小構成の代替 |

## 6. リポジトリ構成

```
.
├── data/                     # ETT データ(課題で提供されたもの)
├── src/ettpoc/
│   ├── data.py               # 読み込み + データ品質フラグ
│   ├── features.py           # ラグ・ローリング・時刻特徴、変化量ターゲット
│   ├── models.py             # persistence / seasonal naive / LightGBM
│   ├── backtest.py           # 月次ローリング分割
│   ├── evaluate.py           # 回帰指標 + イベント検知指標
│   └── pipeline.py           # バックテスト実行
├── tests/                    # 実装より先に書いたテスト(25 件)
├── notebooks/
│   ├── 01_eda.ipynb          # EDA
│   └── 02_results.ipynb      # 結果の評価と図
├── scripts/run_backtest.py   # バックテスト実行スクリプト
├── reports/
│   ├── poc_report.pdf        # クライアント向け報告スライド
│   └── figures/              # スライドに使用した図
└── outputs/                  # 予測結果・集計表(実行時に生成)
```

## 7. 再現手順

```bash
python3.12 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt && pip install -e .
pytest                                       # テスト 25 件
python scripts/run_backtest.py ETTh1 ETTh2   # 約 7 分。outputs/ に予測を出力
jupyter lab notebooks/                       # 01_eda → 02_results
```

macOS で LightGBM を使う場合は `brew install libomp` が必要です。
